## 1. Общие сведения и назначение системы

### 1.1. Наименование разработки
«NutriRec» — персонализированная веб-система рекомендаций по питанию.

### 1.2. Назначение системы
Система предназначена для автоматического подбора рецептов блюд, оптимальных для конкретного пользователя с учетом его:
- антропометрических характеристик (рост, вес, возраст, пол);
- уровня физической активности;
- целевой установки (похудение / поддержание веса / набор мышечной массы);
- медицинских/диетических ограничений (аллергии, непереносимости).

Система реализует RAG-архитектуру *(Retrieval-Augmented Generation)* и предоставляет прозрачное текстовое объяснение причины каждой рекомендации.

### 1.3. Область применения
Система ориентирована на широкую аудиторию пользователей, заботящихся о своём питании: людей, следящих за здоровьем, спортсменов, людей с пищевыми ограничениями.

## 5. Математическая модель персонализации

### 5.1. Шаг 1: Профилирование пользователя

**Расчёт базового обмена веществ (BMR) по формуле Харриса-Бенедикта:**

- Мужчины: `BMR = 88.362 + 13.397 * X + 4.799 * Y - 5.677 * Z`
- Женщины: `BMR = 447.593 + 9.247 * X + 3.098 * Y - 4.330 * Z`

где X — вес (кг), Y — рост (см), Z — возраст (лет).

**Суточная потребность в калориях (TDEE):**

`TDEE = BMR * PAL`

**Корректировка под цель (TDEE_u):**

| Цель | Поправка |
|---|---|
| Похудение | TDEE_u = TDEE × 0.85 (дефицит −15%) |
| Поддержание веса | TDEE_u = TDEE (без изменений) |
| Набор мышечной массы | TDEE_u = TDEE × 1.15 (профицит +15%) |

**Распределение макронутриентов по цели:**

| Цель | Белки | Жиры | Углеводы |
|---|---|---|---|
| Похудение | 30% | 30% | 40% |
| Поддержание | 25% | 30% | 45% |
| Набор массы | 25% | 25% | 50% |

Пересчёт в граммы в сутки:
- `Белки (г) = (доля_белков * TDEE_u) / 4`
- `Жиры (г) = (доля_жиров * TDEE_u) / 9`
- `Углеводы (г) = (доля_углеводов * TDEE_u) / 4`

**Расчёт ИМТ (для отображения пользователю):**

`ИМТ = X / (Y / 100)^2`

| Категория ИМТ | Диапазон |
|---|---|
| Дефицит массы | < 18.5 |
| Норма | 18.5 – 24.9 |
| Избыточный вес | 25.0 – 29.9 |
| Ожирение | >= 30.0 |

### 5.2. Шаг 2: Семантический поиск кандидатов (KNN)

1. Формирование текстового запроса `q` из пользовательского ввода (или автоматически).
2. Векторизация запроса с помощью модели SentenceTransformer в вектор размерности `d`.
3. Поиск `K` ближайших рецептов из ChromaDB по **косинусному сходству**:

```
similarity(q, x_i) = (q · x_i) / (||q|| * ||x_i||)
```

4. По умолчанию: `K = 50` кандидатов.

### 5.3. Шаг 3: Строгая аллерген-фильтрация

Для каждого кандидата `r_i` проверяется пересечение множества аллергенов рецепта `A(r_i)` с аллергенами пользователя `A_u`:

```
A(r_i) ∩ A_u = ∅  →  рецепт ДОПУСКАЕТСЯ к ранжированию
A(r_i) ∩ A_u ≠ ∅  →  рецепт БЕЗУСЛОВНО ОТБРАСЫВАЕТСЯ
```

Это условие **не может быть ослаблено** никакими другими параметрами.

### 5.4. Шаг 4: Нутриентное ранжирование

Целевые показатели на один приём пищи (доля `f_meal = 0.4`, т.е. 40% суточной нормы):

```
E_u_meal = TDEE_u * f_meal
P_u_meal = Белки_u * f_meal
F_u_meal = Жиры_u * f_meal
C_u_meal = Углеводы_u * f_meal
```

**Функция штрафа за отклонение КБЖУ:**

```
Delta(r_i, u) = 0.40 * |E(r_i) - E_u_meal| / E_u_meal
              + 0.30 * |P(r_i) - P_u_meal| / P_u_meal
              + 0.15 * |F(r_i) - F_u_meal| / F_u_meal
              + 0.15 * |C(r_i) - C_u_meal| / C_u_meal
```

**Итоговая функция скоринга** (меньше — лучше):

```
S(r_i | q, u) = alpha * d_i + (1 - alpha) * Delta(r_i, u)
```

где `d_i` — расстояние из ChromaDB (= 1 − косинусное сходство), `alpha = 0.5`.

Топ-`N = 5` рецептов с наименьшим `S` выводятся пользователю.

## 6. Блок генерации объяснений (LLM / RAG)

### 6.1. Концепция RAG в системе

RAG (Retrieval-Augmented Generation) — подход, при котором языковая модель получает на вход **конкретные факты** из базы знаний (данные найденного рецепта + профиль пользователя), а не опирается исключительно на веса, выученные при обучении. Это принципиально снижает вероятность галлюцинаций и делает объяснения верифицируемыми.

### 6.2. Варианты LLM (оба реализуются)

| Вариант | Модель | Преимущества | Недостатки |
|---|---|---|---|
| **Облачный (основной)** | OpenAI API: `gpt-3.5-turbo` или `gpt-4o-mini` | Высокое качество русскоязычной генерации, минимальная настройка | Требует интернет и API-ключ; платный |
| **Локальный (резервный)** | `google/flan-t5-large` (HuggingFace) | Работает без интернета и без API-ключа, бесплатно | Хуже с русским языком; требует дополнительного промпта на EN |

Переключение между вариантами осуществляется через параметр `LLM_PROVIDER` в `config.py`.

### 6.3. Формирование промпта

Промпт передаётся в LLM структурированно и состоит из:
1. **Системной инструкции** — роль AI-диетолога, запрет на вымысел.
2. **Профиля пользователя** — цель, расчётный TDEE, целевые белки/жиры/углеводы.
3. **Данных рецепта** — название, КБЖУ на порцию, список аллергенов.

**Шаблон промпта (OpenAI, русский):**
```
System: Ты — помощник-диетолог. Объясняй строго по данным. Не выдумывай факты.

User:
Профиль пользователя:
  Цель: {goal}
  Суточная калорийность (TDEE): {target_cals} ккал
  Потребность в белке: {target_protein} г/сутки
  Аллергии: {allergens}

Рецепт «{recipe_name}»:
  Калории: {calories} ккал
  Белки: {protein} г | Жиры: {fat} г | Углеводы: {carbs} г

Объясни в 2–3 предложениях, почему этот рецепт подходит данному пользователю.
```

**Шаблон промпта (FLAN-T5, английский):**
```
Explain in 2 sentences why the recipe "{recipe_name}" suits a person
whose goal is {goal}, daily calories target is {target_cals} kcal,
protein target is {target_protein} g. The recipe contains {calories} kcal,
{protein} g protein, {fat} g fat, {carbs} g carbs.
```

### 6.4. Требования к ответу LLM
- Длина: 2–3 предложения
- Язык: русский (для облачного); допустим английский для FLAN-T5
- Запрет на упоминание данных, не переданных в промпте
- Timeout: 8 секунд
- При ошибке / таймауте — автоматическая заглушка-объяснение на основе цифр

## 7. Требования к датасету

### 7.1. Источник данных
Основной датасет: **«Better Recipes for a Better Life»** (Kaggle). При необходимости — дополнение из открытых источников (Open Food Facts и др.).

### 7.2. Обязательные поля рецепта

|---|---|---|
| `id` | str | Уникальный идентификатор |

| `protein` | float | Белки на 1 порцию (г) |

| `allergens` | str | Перечень аллергенов через запятую |
| `image_url` | str | URL изображения блюда (если есть) |

### 7.3. Предобработка (ETL-пайплайн)

1. **Загрузка** — чтение CSV из Kaggle, проверка схемы.
2. **Очистка** — удаление дубликатов, строк с пустыми КБЖУ, нормализация единиц измерения (Pandas, NumPy, re).
3. **Аллерген-разметка** — автоматический маппинг текста ингредиентов на стандартный справочник аллергенов по ключевым словам (regex).
4. **Векторизация** — конкатенация полей `name + description + ingredients` → генерация эмбеддинга SentenceTransformer → загрузка в ChromaDB.
5. **Инициализация** — скрипт `data_processing.py` выполняется **один раз** при первом запуске; ChromaDB сохраняется на диск.

## 9. Требования к безопасности и качеству

### 9.1. Валидация входных данных

- Все числовые поля валидируются на допустимый диапазон перед расчётами.
- При некорректном вводе — дружелюбное сообщение об ошибке, без падения приложения.
- Аллерген-фильтрация выполняется **всегда и безусловно**, её невозможно обойти.

### 9.2. Метрики качества рекомендаций

| Метрика | Пороговое значение |
|---|---|
| Аллерген-конфликты в топ-5 рецептах | 0 (абсолютный запрет) |
| Отклонение калорийности топ-1 от целевого приёма | ≤ 40% |
| Время отклика (поиск + ранжирование, без LLM) | ≤ 5 сек |
| Время отклика (полный пайплайн с OpenAI) | ≤ 10 сек |
| Время отклика (полный пайплайн с FLAN-T5) | ≤ 20 сек (локальный инференс) |

### 9.3. Хранение данных
- API-ключ OpenAI хранится в переменной окружения `OPENAI_API_KEY` или в `config.py` (не публикуется в репозитории).
- Пользовательские данные не сохраняются на сервере — только в рамках текущей сессии Streamlit (`st.session_state`).

## 10. Этапы разработки

| № | Этап | Описание | Результат |
|---|---|---|---|
| 1 | Подготовка данных | Загрузка датасета Kaggle, ETL, аллерген-разметка, векторизация и загрузка в ChromaDB | `data_processing.py` + заполненная ChromaDB |
| 2 | Нутриционный модуль | Реализация `nutrition.py`: BMR, TDEE, БЖУ по полу/возрасту/цели | Юнит-тесты расчётов |
| 3 | Рекомендательный конвейер | Реализация `recommender.py`: KNN-поиск → аллерген-фильтрация → нутриентное ранжирование | Корректный топ-N рецептов |
| 4 | Интеграция LLM (RAG) | Реализация `llm_explainer.py`, шаблоны промптов для OpenAI и FLAN-T5, обработка ошибок | Осмысленные объяснения для каждого рецепта |
| 5 | Разработка UI | Реализация `app.py`: боковая анкета, блок диагностики, карточки рецептов, все состояния | Работающий Streamlit-интерфейс |

## 11. Критерии приёмки (Definition of Done)

- [ ] Пользователь может заполнить анкету (пол, возраст, рост, вес, активность, цель, аллергии) и получить 5 рекомендаций за ≤ 10 секунд
- [ ] Ни один рецепт, содержащий аллерген пользователя, не попадает в выдачу
- [ ] Блок «Ваши нормы» корректно отображает ИМТ, TDEE и целевые БЖУ на основе введённых данных
- [ ] Каждая карточка рецепта содержит текстовое объяснение от LLM
- [ ] При изменении параметров профиля рекомендации автоматически пересчитываются
- [ ] Поддерживается работа без OpenAI API-ключа (через FLAN-T5 fallback)
- [ ] Приложение запускается командой `streamlit run app.py` без ошибок
